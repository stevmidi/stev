# Keyboard Bindings

The keyboard is the primary input surface; every binding arrives as an ordinary `egui::Key` event through `InputPoller` (`src/view/input_poller.rs`). Most keys are matched in `src/core/event_handlers/input_handler.rs` and branch on `ViewState` + `ClipContext`; the marquee-driven Arranger keys, zoom and the clip-panel keys are matched in `Display::forward_input_event` instead — see `020-views-and-state.md` for why. The settings modal and the help overlay (overlays, not views: `Display::overlay`) consume the whole keymap and the pointer while open; ESC closes them (`020-views-and-state.md`). The help overlay shows a curated subset of this file to the user: **changing a binding here means changing its row in `HELP` (`help_overlay.rs`) too.**

The bindings grew out of a physical hardware keypad that is no longer a design target (`archive/010-keypad.md`, read only if the user brings the keypad up). How individual bindings moved over time is in `archive/010-keybindings-history.md`.

## Global

- **Conventional chords are the norm**: ⌘/Ctrl+Z / ⌘/Ctrl+Shift+Z undo/redo (the only undo/redo), ⌘/Ctrl+S saves the current project instantly (opening Save As the first time, for its name), ⌘/Ctrl+⇧+S opens Save As to save it under a typed name (Enter saves, Esc cancels), ⌘/Ctrl+N creates a new project, ⌘Q quits (macOS; the window's close button anywhere) — ⌘/Ctrl+N, opening a project and quitting first prompt when there are unsaved changes (Enter Save, `D` or ⌘/Ctrl+D Don't Save, Esc Cancel; `060` § Unsaved changes), ⌘/Ctrl+O shows the browser panel with the Projects tree focused, ⌘/Ctrl+⌥+B toggles the browser panel (Ableton's browser chord), ⌘/Ctrl+⇧+E exports the lead clip as a `.mid` (Ableton's "Export MIDI Clip", see below; importing one is Enter on it in the browser panel, or a drag onto a lane — `060` § MIDI clip import), ⌘/Ctrl+A selects all, ⌘/Ctrl+, opens the settings modal (below), `?` opens the help overlay (below). When moving a binding, prefer the chord a desktop DAW user (Ableton) would reach for over a single key, and rebind the rarer feature rather than give the everyday one the worse chord.
- **ESC means "never mind"**: closes modals, clears the event selection in `Clip` (a no-op with nothing selected).
- **`Shift+Tab`** shows/hides the clip panel and moves the keyboard between the arranger and the clip view; plain **`Tab`** moves the keyboard between them without touching the layout while both are on screen (see *Clip panel*).
- **Bare `Enter` confirms, and only confirms**: in the modals it confirms the modal; in `Arranger`/`Clip` it fits the tempo to the project's only clip (`FitTempo`, a no-op with more than one clip or a clip already whole bars, `220-capture-without-pending-view.md`). Matched bare-only in `input_handler.rs`.
- **`K` toggles the built-in audio metronome**: `TransportCommand::ToggleMetronomeMute` → `Metronome::toggle_mute`, flipping `SharedAtomics.metronome_mute` (default muted). The click is synthesized in-process by `MetronomeSource` in the `"audio-engine"` thread — see `000-architecture.md`. It clicks while the transport is stopped too, on every beat at the project tempo, all weak (`Metronome::on_tick` accents the bar downbeat only while running). That's deliberate: stopped, the click has no relation to the transport's bars, so it is a steady pulse to play to, and an accent on an arbitrary beat proved distracting. The user can play to it before starting the transport and capture with the stopped `/`. There is no external metronome track or MIDI trigger.
- **`+/-` are generic adjustment keys**: they should mean an increase/decrease in the current context rather than a one-off command unique to a single screen. Today they zoom.
- **Arranger zoom**: `+`/`=` and `-` zoom horizontally ×1.25 per press around the cursor (the viewport centre if the cursor is off-screen); ⌘/Ctrl+wheel and trackpad pinch zoom around the pointer. Bound view-locally in `Display::forward_input_event` (the scale is `Display` state), plain or with Shift (`+` is Shift+`=` on many layouts), never with ⌘/Ctrl — ⌘+/⌘- is egui's UI-scale zoom. Unmodified `+`/`=`/`-` auto-repeat on the OS key-repeat (not `InputPoller`'s DAS/ARR, which tracks egui's logical `key_down` and would stick `+` down if Shift were released first). Bare **`Z`** zooms to the time selection (the marquee across the full width with a 4% margin a side, centred; a no-op without one) and bare **`X`** steps back to the framing the last `Z` replaced (16 deep; any manual zoom clears the history): Ableton's pair. Bare only: `⌘/Ctrl+Z` stays undo, and `⌘/Ctrl+X` arrives as `InputEvent::Cut`. Zoom changes the snap grid too, so plain `←`/`→` steps the cursor one *visible* grid line (a beat at the default zoom, a 16th zoomed in, whole bars zoomed out). See `030-ui-design.md` § Arranger Navigation.
- **Clip-view zoom**: the same `+`/`=`/`-` (plain or Shift) and ⌘/Ctrl+wheel/pinch, around the cursor / pointer, between the whole clip across the width and `MAX_PX_PER_BEAT`. Each clip opens at **home**: its whole reach across the width (window, notes kept outside it, and the headroom bar), frozen while the clip is open, so editing its edges never moves the view. The app never zooms or scrolls the clip view on its own: a two-finger/wheel scroll pans when zoomed in, and the view does not follow the clip cursor. Plain `←`/`→` in `Clip` steps the cursor one visible piano-roll grid line (`GridSurface::PianoRoll`), `Shift+←/→` a raw 16th. Bare **`Z`** frames the selected notes (their hull, at least one beat, 4% margin a side, kept within the clip; a no-op with nothing selected, so `⌘/Ctrl+A` then `Z` fits every note) and bare **`X`** steps back (16 deep; cleared by any manual zoom and on every clip entry/exit). See `030-ui-design.md` § Clip-view zoom.

## Clip Controls (notes selected / not)

- **Selection drives the keys, not a mode**: `Clip` with notes selected (`SharedAtomics::has_event_selection`, `020-views-and-state.md` § Views) turns the arrows, `Delete`, `M` and `⌘/Ctrl+D` into note edits; clearing the selection (ESC, or clicking an empty grid spot) turns them back into cursor navigation. Select by click, marquee drag, or `⌘/Ctrl+A` (select all, keyboard-only).
- **Note edits, all simultaneously active**: `L/R` = position at the grid step (`NudgeSelectedEvents`), `⌘/Ctrl+L/R` = position at a much finer step (same command, `FINE_NUDGE_TICKS` in `input_handler.rs` — a standalone tunable, currently 10 ticks), `Shift+L/R` = length (`NudgeSelectedEventsLength`), `Up/Down` = pitch (`TransposeSelectedEvents`), one semitone per press, an octave with Shift. With notes selected the arrows nudge by a fixed 64th regardless of zoom. F1–F4 are unassigned in `Clip`.
- **Double-click empty grid inserts a note** (`InputEvent::MouseDoubleClicked` → `Display::handle_double_click` → `InsertNote`, undoable): at the row clicked, starting on the grid line the hover cursor line shows, at the last-used length/velocity (a beat at 100 until a resize sets them); it becomes the selection and is auditioned.
- **Drag a note to move it, drag its edge to resize it** (`020` § Note Move & Resize Drag, one `DragNotes` undo step per drag, Esc cancels mid-drag): the body moves in time (whole grid steps) and pitch (auditioned), the left/right edge resizes (resize cursor on hover). A selected note drags the whole selection; an unselected one is selected and drags alone.
- **Drag on the octave legend (left of the keys) zooms and scrolls the rows** (Ableton / Bitwig): horizontal = row height (right = taller), vertical = scroll, the grabbed row staying under the pointer; magnifying-glass pointer on hover, hidden and held in place during the drag. View state only, not undoable. `030` § Piano Roll.
- **`⌘/Ctrl+C` / `⌘/Ctrl+X` / `⌘/Ctrl+V` copy, cut and paste notes** in `Clip` (`CopyNotes` / `CutNotes` / `PasteNotes`; cut and paste undoable): copy takes the selected notes (none selected → no-op), paste lands the earliest one on the clip cursor with the rest keeping their spacing, into any clip, and selects the pasted notes. `⌘/Ctrl+D` duplicates the selection flush after itself through the same paste (the note twin of the arranger's Duplicate Clips; bare `D` is spare) (keeps mute, trims same-pitch overlaps, drops copies past the clip end). A separate clipboard from the arranger's clips; the `⇧` forms do nothing in `Clip`. See `020` § Note Copy / Cut / Paste.
- **Velocity: ⌘/Ctrl+drag edits it, no key does** (`DragEventsVelocity`, `020` § Velocity Drag). The velocity panel (`VELOCITY_PANEL_H`) is always shown in `Clip`, display only.
- **Bare `M` mutes the selected *events*** (`SequencerCommand::MuteSelectedEvents` → `MuteSelectedEventsEdit`, undoable, each `NoteOn` with its paired `NoteOff`). In plain `Clip` it does nothing; there is no whole-clip mute toggle anywhere — a clip is only muted through a tick range (the Arranger's marquee `M`). See `020-views-and-state.md` and `050-undo-redo.md`.
- **Bare `Q` quantizes** (`SequencerCommand::QuantizeEvents` → `QuantizeEventsEdit`, undoable): the selected notes, or with none selected every note in the clip's window — the one clip key that acts on the whole clip when nothing is selected. The selection is kept. There is no `Q` in the Arranger. See `070-quantization.md`.
- **`⌥=`/`⌥-` stretch the whole clip a bar longer/shorter** in `Clip` (`SequencerCommand::RescaleSelectedClipTempo` → `RetimeClipEdit::rescale_selected`, undoable — its undo puts the tempo back too): the region grows/shrinks by one bar and the notes are retimed to fill it, the window start kept on a bar line of the event space as Enter's fit leaves it (so a following Enter has nothing to do); when it is the only clip, the project tempo moves with it, and so does the loop region, as with every edit to the only clip (`220`). It fixes a take whose bar count came out wrong; ⌥ echoes Logic's Option-drag time-stretch. Handled in `input_handler.rs`'s `handle_plus_minus_keys` — the view-side zoom arm refuses ⌥ so it falls through. On macOS `⌥=` types `≠`, but egui-winit falls back to the physical key, so it arrives as `Key::Equals` + alt.
- **Cursor in plain `Clip`**: `Left/Right` step the clip cursor one grid line, `Shift` a raw 16th. `⌘←/→` and `⌥←/→` are unbound; `⌥←/→` is kept free for a future jump to note edges, mirroring the arranger's clip-edge jump. A future `Shift+L/R` meaning with *no* event selected (dragging a time selection) is not implemented; today `Shift+L/R` always means length.
- **The clip panel: `Shift+Tab` shows/hides it, `⌘⌥E` sizes it.** From the arranger `Shift+Tab` shows the clip view and gives it the keyboard; from the clip view it hides it and gives the keyboard back, at the panel's current size — **maximized** (the whole lane area) or **docked** below the arranger. The app starts docked and shown, with the arranger holding the keyboard. `⌘⌥E` flips between the two sizes in `Arranger` and `Clip`; with the panel hidden it only changes the size it will show at. Bound view-locally in `forward_input_event` (panel layout is `Display` state), ahead of the `⌘E` split arm, which refuses ⌥ (and ⇧, the clip export). Docked, **a click focuses the pane it lands in** (`InputEvent::FocusPane` → `SequencerCommand::FocusPane`, sent ahead of the click's own events), and `Shift+Tab` with the arranger focused hides the panel (consumed in the view, since the handler would send `EnterClip`). **Plain `Tab` moves the keyboard to the other pane**, changing the layout only as much as that needs: docked it sends the same `FocusPane` a click does and shows/hides nothing (focusing the clip view drops the arranger's time selection, as a click does); hidden or maximized the other pane is off screen, so it falls through to the handler and does what `Shift+Tab` does. Bare only (`is_pane_focus_key`, `input_event.rs`): `Ctrl+Tab` is the settings modal's tab step. With the track headers focused it gives the keyboard back to the lanes and then swaps, as `Shift+Tab` leaves and then toggles. With the **browser panel** focused it only gives the keyboard back to the focused pane — no swap — so finishing in the browser is one press (`handle_browser_key`, which also disarms a pending delete). Logic Pro's Tab, which cycles key focus between working areas; Ableton's Tab (Session/Arrangement) has nothing to clash with here. The wheel, pinch and two-finger scroll go to the pane under the pointer; `+`/`-`/`Z`/`X` to the focused pane.

- **`⌘/Ctrl+⇧+E` exports the lead clip** as a Standard MIDI File, in `Arranger` and `Clip` alike: always the whole clip as it plays, whatever part of it the marquee or the note selection covers. In the arranger a marquee touching more than one clip refuses ("Select a single clip to export") rather than picking one; merge them first (`⌘/Ctrl+J`). No dialog: the file lands next to the project and the footer says what happened (`060-persistence.md` § MIDI clip export). Bound in `Display` (the marquee and the project folder/name are view state), ahead of the `⌘E` split arm, which refuses ⇧.

## Settings Modal

- **`⌘/Ctrl+,` opens the settings modal** over the arranger or the clip view, from any key focus (lanes, track headers, browser); pressing it again closes it, as `Esc` does; the view underneath never changed. Ignored while a text field or dialog has the keyboard (track rename, tempo field, Save As, the unsaved-changes prompt) — those take every key. Bound in `Display` (`settings_modal.rs`), after the keyboard marquee-nudge guard.
- **Tabs**: `⌘⇧]` / `⌘⇧[` (macOS; the shifted `}`/`{` forms are matched too) and `Ctrl+Tab` / `Ctrl+⇧Tab` (everywhere — `KeyModifiers::ctrl`, the one Control-everywhere chord) step to the next / previous tab, wrapping; a click on a tab shows it. It opens on the tab last used this session, MIDI after launch.
- **MIDI tab**: `Tab` / `←` / `→` cycle IN PORT → OUT PORT → OUT OFFSET; `↑`/`↓` move the focused port list's cursor, or nudge the offset (applied and saved on every nudge); `Enter` connects the port under the cursor (a cursor move never touches hardware).
- **Appearance tab**: `↑`/`↓` step through the themes, wrapping; each is applied **and saved** as it is reached — there is no separate default. `⇧F5`/`⇧F6` do the same from anywhere.
- **No F-key opens anything** (F1–F4 unbound since 2026-10-06). Projects and plugins are browsed in the browser side panel (⌘/Ctrl+O, ⌘/Ctrl+⌥+B), not a modal; a track's MIDI channel is set, and its plugin removed, from the output chip on its header — mouse-only (`020-views-and-state.md` § Track Header Output Chip & Menu). ⌘/Ctrl+S, ⌘/Ctrl+⇧+S (switches to the new name as the current project) and ⌘/Ctrl+N never open anything.

## Help Overlay

- **`?` opens the keyboard help overlay** — one page of the bindings a stranger needs, in three columns (`help_overlay.rs`'s `HELP` table) — and `?` again, `Esc` or a click anywhere closes it; the wheel scrolls it in a window too short for the page. Matched as `Key::Questionmark` with no ⌘/Ctrl or ⌥, ⇧ ignored: egui-winit reports the logical key, so it is `⇧/` on US layouts and `⇧+` on Nordic ones, wherever the layout puts `?`, and it arrives as `Questionmark`, never as `Slash` (Commit) or `Plus` (zoom). From any key focus (lanes, track headers, browser); ignored while a text field or dialog has the keyboard and while the settings modal is up (each takes every key). Bound in `Display`'s `forward_input_event`, beside `⌘/Ctrl+,`. The header's `?` chip is its mouse twin.
- **Key labels are spelled out**: the table is written with `⌘` `⌥` `⇧` and shown as `Cmd+` / `Opt+` / `Shift+` on macOS and `Ctrl+` / `Alt+` / `Shift+` elsewhere (`key_label`) — egui's bundled fonts have no `⌥` or `⌫`.

## Arranger Region and Marquee Controls

- **`⌘/Ctrl+L`** is the only region control: it snaps the region to the current time selection if one spans real time (`TransportCommand::SetRegionOrToggleLoop`), otherwise toggles looping in place (`TransportCommand::ToggleLoop`, the region band stays put). Both go through the single `InputEvent::SetRegionToTimeSelectionOrToggleLoop` arm in `input_handler.rs`, with no sequencer round-trip. The selected clip is deliberately *not* an operand — the arranger nearly always has a clip selected, so a clip fallback would swallow the toggle. The loop region has no grow/nudge/to-cursor shortcut; `+`/`-` zoom.
- **Selection keys** (a *selection* control; only `⌘/Ctrl+L` commits it to the region): `Shift+L/R` drags the time selection's free edge one visible grid step; `Shift+Up/Down` drags its *track* span (`Display::nudge_time_selection_track`); `⌥←/→` jumps the cursor to the next clip edge on the selected track and `⇧⌥←/→` drags the selection's free edge there — the everyday way to select exactly one clip (cursor on its start, `⇧⌥→`) before `⌘/Ctrl+L`. `⌘/Ctrl+←/→` (ghost-nudged, committed on ⌘/Ctrl release) moves the marqueed block.
- **Marquee edits** (details and track-scoping in `020-views-and-state.md` § Arranger Time Selection):
  - `Delete`/`Backspace` — carve the selection out, scoped to the marqueed tracks.
  - `Shift+⌘/Ctrl+M` — "Insert MIDI Clip" (Ableton's chord): an empty clip on the selected track over the marquee's tick range, or one bar at the cursor with no marquee (or a zero-width one); a no-op if it would overlap any clip (`SequencerCommand::InsertEmptyClip` → `CommitClipEdit::from_empty_clip`, undoable). Plain `⌘M` is left to macOS (minimize). `Shift+Tab` never creates a clip: over empty space it shows the panel with "No clip at the cursor".
  - `⌘/Ctrl+E` — split clips at the cursor (Ableton-style).
  - `⌘/Ctrl+J` — merge the clips in the marquee into one per marqueed track (Ableton's Consolidate).
  - `⌘/Ctrl+I` — insert silence at the selection start, always every track.
  - `⌘/Ctrl+Delete` — "Delete Time", the opposite of `⌘/Ctrl+I`: carve then close the gap, every track.
  - `⌘/Ctrl+D` — "Duplicate Clips": paste the marquee's content flush after itself on the marqueed tracks only, overwriting what sits there; nothing shifts; the marquee advances so presses chain.
  - `Shift+⌘/Ctrl+D` — "Duplicate Time": insert silence at the selection end across every track, paste every track's slice into the gap, advance the selection; a loop region within/after the selection is slid along, not resized. Same ⇧-means-wider shape as `⌘/Ctrl+C` vs `Shift+⌘/Ctrl+C`. There is no bare `D` duplicate.
  - `M` — mute the range (`MuteInRangeEdit`); with no marquee the press is consumed.
  - `⌘/Ctrl+A` — marquee the hull of every clip.
- **Tracks** (Arranger; `020-views-and-state.md` § Tracks and Regions, `050-undo-redo.md` § Track add / remove — both undoable):
  - `⌘/Ctrl+T` — add an empty MIDI track after the selected one, on the lowest MIDI channel no other MIDI track uses, and select it (Ableton's chord). Refused at 16 tracks. Bare `T` stays tap tempo; with ⌘ it no longer taps.
  - `Delete`/`Backspace` **with the track headers focused** (a click on a header's empty area — `020` § Track Header Focus) — delete the selected track: its clips, plugin and mix settings; the track that took its place is selected and the headers keep the keyboard, so presses chain. Refused on the last track. Plain only: a modified Delete falls through to the arranger as usual (`⌘/Ctrl+Delete` is Delete Time). `↑`/`↓` still move the track selection; `Esc` (or `Shift+Tab`, which still shows/hides the clip panel) gives the keyboard back to the lanes. With the lanes focused, `Delete`/`Backspace` is the marquee carve above. (`⌘/Ctrl+⌫` deleted the track until 2026-10-05 — one modifier from the carve and Delete Time — and is now unbound: it falls through to the carve like any modified Backspace.)
  - `⌘/Ctrl+R` — rename the selected track (Ableton's chord): an inline text field over its header's name row (`020` § Track Rename). While it is open it takes every key — `Enter` commits, `Esc` cancels, everything else is typing. Exact chord, bound in `Display` ahead of bare `R` (live record), which no longer fires with ⌘.
  - In the browser panel (while it has the keyboard), `⌘/Ctrl+R` renames the selected project or `.mid` file instead, with the same kind of inline field over its row (`020` § Views). Bound in `handle_browser_key`, ahead of the track's.
  - The mouse twins: the `+` row under the last lane adds a track at the end; a double-click on a header's name renames that track; the track header's output menu ends in **Rename** and **Delete track** for its own track.
- **Bound in `Display`, not `input_handler.rs`**: `⌘/Ctrl+A`, `⌘/Ctrl+L`, `Shift+L/R`, `Shift+Up/Down`, `⌘/Ctrl+D`, `Delete`/`Backspace`, `⌘/Ctrl+Delete`, `⌘/Ctrl+T`, `⌘/Ctrl+R`, the track-header focus keys (`track_header_key`), the rename, BPM and meter fields' keys and presses (`field_event`), `⌘/Ctrl+E`, `⌘/Ctrl+⇧+E`, `⌘/Ctrl+J`, `M`, `Shift+⌘/Ctrl+M`, `⌘/Ctrl+I`, plain `←`/`→`, `+`/`=`/`-` and bare `Z`/`X` — see `020-views-and-state.md` for why, and for how the marquee is captured and cleared.

## Transport

Cubase-style, layered on top of `Space`'s Ableton-style toggle; all are live in every non-modal view:

- **`Space`**: `TransportCommand::TogglePlayback` — starts if stopped, stops if running (position stays where it stopped).
- **`⌥Space`**: Cubase's "Start" — an unconditional restart, no stop press needed. In `Clip` it restarts from the **clip cursor** (`SequencerCommand::PlayFromClipCursor` → `TransportCommand::PlayFromTick`, `stop(); jump_and_chase(tick); start()`) and leaves the arranger cursor where it is, while bare `Space` starts from the arranger cursor: park the arranger cursor before an edit, and `Space` replays the edit in context while `⌥Space` plays from where you're editing. In `Arranger` it is the same as bare `Space`. Both `⌥Space` arms are matched ahead of the bare `Space` arm in `input_handler.rs`.
- **`0`**: `TransportCommand::Stop` — an unconditional stop that also resets the cursor-side position (`reset_playback_to_cursor`). egui-winit maps `Numpad0`/`Digit0` to the same `Key::Num0` (it merges numpad and main row for digits, `Enter`, `/`, `-`), so main-row `0` is Stop too.
- **`\` or `/` (`Key::Backslash`, `Key::Slash`)**: `SequencerCommand::Commit`. `\` is the key shown (help overlay, README): a single press beside `[` `]` on US ANSI and Norwegian Windows layouts. `/` stays, main row or numpad, for layouts where `\` takes a chord (Swedish, Danish, German). Added 2026-10-08; the docs still call the commit "the `/`" (the stopped `/`, the running `/`). It freezes the capture into a new clip, or into the lead clip:
  - playing, no lead clip: the last pass (`CommitClipEdit::from_running_capture`, `100-running-capture.md`);
  - stopped, no lead clip: the phrase detection frames it, and the clip keeps the rest of the capture outside its window (`CommitClipEdit::from_stopped_capture`, `040-phrase-detection.md`);
  - with a lead clip under the cursor: one undoable `InsertCaptureEdit` into that clip — the last pass while playing, the detected phrase at the clip cursor while stopped.

  All go through `commit_clip_workflow` (`clip_lifecycle.rs`), are no-ops on an empty buffer, and are undoable; the buffer stays cleared either way (`050-undo-redo.md`). `/` sits at a findable-by-feel edge (bottom-right of the main row; top-left of the numpad), and egui-winit maps `Slash`/`NumpadDivide` to the same key.
- **`[` / `]`**: move the start / end edge of a clip to the cursor, undoably (`SetClipEdgeToCursor`, `ResizeClipEdit`). In `Arranger` an arrangement trim at the arranger cursor, on the clip under it or the nearest one on that side. In `Clip` a marker on the lead clip at the clip cursor: `[` moves only the start (the end stays; the clip keeps its place and its length follows), `]` ends it — exactly at the cursor while the project has one clip, otherwise rounded **up** to the bar the cursor is in. They never move the playhead (the current pass plays out and the next wrap picks up the new window). While the project has one clip the loop is that clip and follows its edges (the first stopped `/` also turns looping on), so its end can be judged against the wrap; then **`Enter` fits the tempo** so the length becomes whole bars (`SequencerCommand::FitTempo` → `RetimeClipEdit::fit_sole_clip`, undoable, works while playing). The clip cursor can go one bar past the end (`CLIP_END_HEADROOM_BARS`), so `→` then `]` lengthens as easily as `←` then `]` shortens. Any modifier but ⌘/Ctrl (Nordic layouts type brackets with ⌥). Details in `020-views-and-state.md` § "Clip Edge Drag-Resize"; why in `220-capture-without-pending-view.md`.
- **`T`**: tap tempo (`SequencerCommand::TapTempo` → `time::TapTempo`): from the third tap of a burst (taps under 2 s apart) the average spacing of its last eight sets the tempo, 20–300 BPM. One undo step per burst (`SetTempoEdit`, merged by `TempoGesture::Taps`). The header's BPM chip is the mouse twin — drag it, or double-click it to type a value (`030` § Header & Footer); its field takes every key while open, like the rename field (`field_event`).
- **Spare**: `Period`, numpad `1`–`9` (same egui-winit merging caveat), bare `S`, `D`, `U`, bare `Enter` outside the tempo fit, `Shift++`.

## Retired bindings — do not reintroduce

- **`Shift+Tab` creating an empty clip** when the arranger cursor sat in empty space: `Shift+Tab` is show/hide only; `Shift+⌘/Ctrl+M` inserts an empty clip.
- **`Shift+Enter`** is unbound everywhere (keypad-era "back/cancel"); ESC and `Shift+Tab` cover it.
- **F1–F4 mode switching in `Clip`** (`ClipEditMode`) is gone — each axis has its own fixed binding.
- **`Shift+-`** no longer clears the event selection (ESC only), and **Shift+`+`/`-`** no longer stretch the clip (`⌥=`/`⌥-`): both freed for zoom.
- **`Period`** is not Stop (`0` alone is).
- **`F19`/`⇧F19`** undo/redo, the parked keyboard velocity nudge, `ClipCursorMode`, `ExtendEventSelection`, and `Shift+Up/Down` region-to-cursor were deleted outright, not left dead.
- **A whole-clip `M` toggle** or a selected-clip `Delete` fallback — the Arranger's `M` and `Delete` are marquee-only on purpose.
- **`Q` in the Arranger** (the marquee quantize) — quantize lives in `Clip` only.
- **F2 / F3 opening the MIDI settings / Themes modals**, and F3 as a focus-swap key inside them — one settings modal on `⌘/Ctrl+,` replaced both (2026-10-06).

## Loop State

Playback loop wrapping is gated by `Transport.loop_enabled` (mirrored in `SharedAtomics.loop_enabled`, defaults `true`). `Transport::tick()` only wraps at the region boundary when `is_loop_enabled()` is true; otherwise playback runs straight through the region end. On a wrap it returns `TickOutcome::Wrapped(region_start)` (otherwise `Advanced`); the `"sequencer"` thread's tick pump re-anchors playback **synchronously** — `EventHandlers::reanchor_playback` (re-seek tracks, realign the clock, release sounding notes) — before the next `Sequencer::tick`. The wrap does **not** send a `TransportEvent`: deferring the re-anchor through `transport_event_rx` let a burst of ticks drained in one wakeup run past the region end into the next clip (`150-clock-position-sync.md`). `⌘/Ctrl+L` mimics Ableton Live's loop-region toggle via `Transport::set_region_or_toggle_loop`: if the region already matches the requested bounds it toggles `loop_enabled` instead of re-applying the same region; setting a genuinely different region always re-enables looping. With no time selection the press is a bare `loop_enabled` flip, so `⌘/Ctrl+L`, `⌘/Ctrl+L` turns looping off and back on in place. The set-or-toggle command is deliberately operand-agnostic, so any future region source routes through it rather than growing a parallel path. The region band in the timeline (`draw_region`) is dimmed when looping is disabled.
