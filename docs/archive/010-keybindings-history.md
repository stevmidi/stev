# Keyboard Bindings

The keyboard is the primary input surface; every binding arrives as an ordinary `egui::Key` event through `InputPoller` (`src/view/input_poller.rs`). Most keys are matched in `src/core/event_handlers/input_handler.rs` and branch on `ViewState` + `ClipContext`; the marquee-driven Arranger keys are matched in `Display::forward_input_event` instead — see `020-views-and-state.md` for why. Modals (`Project`, `MidiSettings`, `Track`, `Themes`) consume the whole keymap while open, ESC closes every one of them (`020-views-and-state.md`).

The bindings grew out of a physical hardware keypad that is no longer a design target; its layout and the keypad-era chords that were retired live in `archive/010-keypad.md`, which is intentionally not indexed — read it only if the user brings the keypad up.

## Global

- **Conventional chords are the norm**: ⌘/Ctrl+Z / ⌘/Ctrl+Shift+Z undo/redo, ⌘/Ctrl+S saves the current project instantly, ⌘/Ctrl+⇧+S saves it under a freshly generated name ("Save As"), ⌘/Ctrl+N creates a new project, ⌘/Ctrl+O opens the Project modal, ⌘/Ctrl+A selects all. When moving a binding, prefer the chord a desktop DAW user (Ableton) would reach for over a keypad-era single key.
- **`SHIFT+ENTER` is unbound everywhere**: it was the keypad-era "back/cancel" chord. ESC means "never mind" (closes modals, clears the event selection), `Shift+Tab` toggles between Arranger and clip view (enters the clip from Arranger, exits from `Clip`), and the old Arranger meaning (`SelectClipsInRegion`) was deleted outright. Do not reintroduce a `SHIFT+ENTER` binding.
- **Bare `Enter` confirms, and only confirms**: in the modals it confirms the modal, in `Arranger`/`Clip` it fits the tempo to the project's only clip (`FitTempo`, a no-op with more than one clip or a clip already whole bars, `220-capture-without-pending-view.md`), and it does nothing else. (Until 2026-09-26 it also confirmed the pending phrase in the retired `PendingClip` view.) Entering the selected clip moved onto `Shift+Tab` (above), and the transport "Start" it then carried moved onto `⌥Space` (2026-09-25, see Transport). Matched bare-only in `input_handler.rs` (`Shift+Enter` stays unbound).
- **`K` toggles the built-in audio metronome**: `TransportCommand::ToggleMetronomeMute` → `Metronome::toggle_mute`, flipping `SharedAtomics.metronome_mute` (default muted). The click is synthesized in-process by `MetronomeSource` in the `"audio-engine"` thread — see `000-architecture.md`. There is no external metronome track or MIDI trigger.
- **Bare `S`, `D`, `U` are unassigned**: their old single-key meanings all moved to ⌘/Ctrl chords (above).
- **`+/-` are generic adjustment keys**: they should usually mean apply an increase/decrease in the current mode rather than a one-off command unique to a single screen.
- **Arranger zoom** (the clip views too — see the end of this entry): `+`/`=` and `-` zoom the arranger horizontally ×1.25 per press around the cursor (the viewport centre if the cursor is off-screen); ⌘/Ctrl+wheel and trackpad pinch zoom around the pointer. Bound view-locally in `Display::forward_input_event` (the scale is `Display` state), plain or with Shift (`+` is Shift+`=` on many layouts), never with ⌘/Ctrl — ⌘+/⌘- is egui's UI-scale zoom. Unmodified `+`/`=`/`-` auto-repeat on the OS key-repeat (not `InputPoller`'s DAS/ARR, which tracks egui's logical `key_down` and would stick `+` down if Shift were released first). Bare **`Z`** zooms to the time selection — the marquee across the full width with a 4% screen margin a side, centred — every selection length lands on the same span of screen; a no-op without one — and bare **`X`** steps back to the framing the last `Z` replaced (repeatable through consecutive `Z`s, 16 deep; any manual zoom clears it, so `X` after `+`/`-`/wheel/pinch does nothing): Ableton's pair. Both are bound view-locally in `forward_input_event`, bare only: `⌘/Ctrl+Z` stays undo, and `⌘/Ctrl+X` never arrives as a key press (it is `InputEvent::Cut`). Only `Z` feeds the history — `+`/`-`, wheel and pinch are continuous, undone the way they were made, and clear it. Zoom changes the snap grid too, so plain `←`/`→` steps the cursor one *visible* grid line (a beat at the default zoom, a 16th zoomed in, whole bars zoomed out). See `030-ui-design.md` § Arranger Navigation and `archive/190-arranger-zoom.md`. **Clip views** (`Clip`, phase 1 of `archive/200-clip-view-zoom.md`): the same `+`/`=`/`-` (plain or Shift) and ⌘/Ctrl+wheel/pinch zoom, around the cursor / pointer, between the whole clip across the width and `MAX_PX_PER_BEAT`; zooming out stops at the whole clip. Each clip opens at **home**: its whole reach across the width (window, notes kept outside it, and the headroom bar), frozen for as long as the clip is open, so editing its edges never moves the view (2026-09-26, `220-capture-without-pending-view.md`; the 8-bar cap and cursor-follow of `210` phase 4 are gone). Zooming in and back out lands home again. The app never zooms or scrolls the clip view on its own: a two-finger/wheel scroll pans when zoomed in, and the view does not follow the clip cursor. Zoom changes the clip views' snap grid too (phase 2, the piano-roll surface of `grid_tiers`): plain `←`/`→` in `Clip` steps the cursor one visible grid line (the zoom-adaptive piano-roll grid, `GridSurface::PianoRoll`), and `Shift+←/→` a raw 16th; with notes selected the arrows still nudge them by a fixed 64th. Bare **`Z`** frames the selected notes (their hull, at least one beat, with the arranger's 4%-a-side margin, centred and kept within the clip; a no-op with nothing selected, so `⌘/Ctrl+A` then `Z` fits every note) and bare **`X`** steps back through those `Z`s (16 deep; cleared by any manual zoom and on every clip entry/exit) — phase 3; `Z` on a selection spanning the whole clip lands back on fit.

## Clip Controls (notes selected / not)

- **No more F1–F4 mode switching**: the old `ClipEditMode` softkey mode-switch (F1 Position / F2 Length / F3 Pitch / F4 Velocity, `+/-` doing whatever the active mode meant) is gone. Each axis has its own fixed binding instead: `L/R` = position at the grid step (`NudgeSelectedEvents`), `⌘/Ctrl+L/R` = position at a much finer step (same command, `FINE_NUDGE_TICKS` in `input_handler.rs` — a standalone tunable constant, currently 10 ticks, not derived from any grid resolution), `Shift+L/R` = length (`NudgeSelectedEventsLength`, moved off `+/-` — see below), `Up/Down` = pitch (`TransposeSelectedEvents`) — Up raises, Down lowers, one semitone per press, an octave (12 semitones) with Shift. All of these are simultaneously active — there is no mode to switch. F1–F4 are spare/unassigned in `Clip`, same as Arranger's spare F4; `+`/`=`/`-` zoom there as in the Arranger (see Global), and `⌥=`/`⌥-` stretch the clip (below).
- **Velocity: ⌘/Ctrl+drag edits it, no key does**: the parked keyboard nudge (`SequencerCommand::NudgeSelectedEventsVelocity`, kept wired but unbound) was removed 2026-09-24 as having no planned use; the ⌘/Ctrl+drag gesture (`DragEventsVelocity`, `020` "Velocity Drag") is the one velocity edit. The velocity panel itself (`VELOCITY_PANEL_H`) is unconditional in `Clip` — shown whether or not an event is selected, display only, not yet interactive.
- **The clip panel: `Shift+Tab` shows/hides it, `⌘⌥E` sizes it** (`archive/210-docked-clip-panel.md`). `Shift+Tab` keeps its meaning: from the arranger it shows the clip view and gives it the keyboard, and from the clip view it hides it and gives the keyboard back. It does that at the panel's current size, **maximized** (the whole lane area) or **docked** below the arranger. The app starts with it shown and docked, with the arranger holding the keyboard. `⌘⌥E` flips between the two sizes, in `Arranger` and `Clip`; with the panel hidden it only changes the size the panel will show at. Bound view-locally in `forward_input_event` (the panel is `Display` layout state), ahead of the `⌘E` split arm, which now refuses ⌥ (it used to fire on `⌘⌥E` too). Docked, **a click focuses the pane it lands in** (`InputEvent::FocusPane` → `SequencerCommand::FocusPane`, sent ahead of the click's own events), and `Shift+Tab` with the arranger focused hides the panel (consumed in the view, since the handler would send `EnterClip`). The wheel, pinch and two-finger scroll go to the pane under the pointer; `+`/`-`/`Z`/`X` to the focused pane.
- **`Shift+L/R` no longer touches selection**: it used to extend/shrink an anchored event-selection range (`SequencerCommand::ExtendEventSelection`); that command, its workflow, and the underlying `Clip`/`Selection` anchor machinery have been deleted outright (superseded by marquee selection — see "Event Marquee Selection" in `020-views-and-state.md`). `⌘/Ctrl+A` selects all events (moved off `Shift++`) and only Esc clears the selection — `Shift+-` did too until 2026-09-24, and was deleted to free Shift+`+`/`-` for zoom. A future iteration will give `Shift+L/R` an Arranger-style meaning in `Clip` when *no* event is selected (dragging a time selection for bulk operations); that is not implemented yet — today `Shift+L/R` always means length, event-selection state or not.
- **`⌥=`/`⌥-` stretch the whole clip a bar longer/shorter** in `Clip` (`SequencerCommand::RescaleSelectedClipTempo` → `rescale_selected_clip_tempo`): the region grows/shrinks by one bar and the notes are retimed to fill it; when it is the only clip, the project tempo moves with it. It fixes a take whose bar count came out wrong. Moved off Shift+`+`/`-` (then `Clip`-only) on 2026-09-24 so Shift+`+`/`-` could zoom like the Arranger's; ⌥ echoes Logic's Option-drag time-stretch. A whole-clip op, so the event selection doesn't matter. Handled in `input_handler.rs`'s `handle_plus_minus_keys` — the view-side zoom arm refuses ⌥ so it falls through. On macOS `⌥=` types `≠`, but egui-winit falls back to the physical key when the logical one doesn't map, so it arrives as `Key::Equals` + alt.
- **Selection drives the keys, not a mode**: editing used to be a `ClipEdit` view, first a manual ENTER toggle, then entered automatically on selecting; it is now just `Clip` with notes selected (`SharedAtomics::has_event_selection`, see "Views" in `020-views-and-state.md`), collapsed 2026-09-24. Selecting an event (click, marquee drag, or `⌘/Ctrl+A` selecting all — moved off `Shift++`, which is now spare; keyboard-only like the other `⌘/Ctrl` chords) turns the arrows, `Delete`, `M` and `D` into note edits; clearing the selection (ESC, or clicking an empty grid spot) turns them back into cursor navigation. ENTER has no remaining job inside `Clip` or `Arranger` — it is a spare key.
- **ESC deselects**: clears the event selection in `Clip`; a no-op with nothing selected. `Shift+Tab` is the only way back to `Arranger` (moved off `Shift+Enter`, which is now unbound everywhere — the Ableton-style chord is what a keyboard user reaches for), and — from `Arranger` — the only way into the selected clip (moved off bare `Enter`, see above).
- **Bare `M` toggles the selected *events* in `Clip`, not the clip**: `input_handler.rs`'s `handle_mute` branches on `ClipContext` — `ClipWithSelection` sends `SequencerCommand::MuteSelectedEvents` (`MuteSelectedEventsEdit`, undoable, mutes each selected `NoteOn` and its paired `NoteOff` together), and the Arranger's `M` is marquee-only (`MuteClipsInRange`/`MuteInRangeEdit`, resolved in the view — with no marquee the press is consumed). There is no whole-clip toggle anywhere any more (`MuteSelectedClipsEdit` was deleted outright): `M` inside plain `Clip` does nothing, and a clip is only ever muted through a tick range. Before this split, a bare `M` press with notes selected muted the whole clip out from under the events being edited — see `020-views-and-state.md` and `050-undo-redo.md`.
- **`Left/Right` in plain `Clip`** (no selection) step the clip cursor one grid line, `Shift` a raw 16th. There is no cursor *mode* any more: `ClipCursorMode` (`Grid` / `Event`, the latter stepping between note onsets in `PendingClip`) was deleted with that view on 2026-09-26, since only `Grid` was ever left. In `Clip` with nothing selected, `⌘←/→` and `⌥←/→` are unbound (they used to fall through to a 16th cursor step with the modifier ignored); `⌥←/→` is kept free for a future note-edge jump. The keypad's duplicate undo/redo on `F19`/`⇧F19` was removed the same day — `⌘/Ctrl+Z` / `⇧⌘/Ctrl+Z` are the only undo/redo.

## Arranger Function Keys

- **Arranger F-keys**: F1=TRACK, F2=SETTINGS (MidiSettings), F3=THEMES, F4=spare. The Project modal is not on a softkey at all — it's opened only via ⌘/Ctrl+O. ⌘/Ctrl+S saves the current project instantly, ⌘/Ctrl+⇧+S ("Save As") saves it under a freshly auto-generated name and switches to that name as the current project, and ⌘/Ctrl+N creates a new one instantly; none of the three ever opens a modal. See `020-views-and-state.md` for the Project modal's own (now minimal) keys, and for the `Themes` modal.

## Arranger Region Controls

Region mutation is always available directly in `Arranger` via `⌘/Ctrl+L`, which snaps the region to the current time selection if one spans real time, otherwise toggles looping on/off in place (the region band stays where it is). The selected clip is deliberately *not* an operand — the arranger nearly always has a clip selected, so a clip fallback would swallow the toggle. Plain `+`/`-` and `Shift+/-` never touch the region in `Arranger` — they zoom (see Global) — the loop region has no keyboard "grow"/"nudge" shortcut of its own, only `⌘/Ctrl+L`, and clip region length is edited only by dragging the clip header band's edge (see `020-views-and-state.md`). Both `⌘/Ctrl+L` branches route through the single `InputEvent::SetRegionToTimeSelectionOrToggleLoop` arm in `input_handler.rs`, which sends `TransportCommand::SetRegionOrToggleLoop` for a selection and `TransportCommand::ToggleLoop` for none — no sequencer round-trip either way. `SHIFT+L/R` no longer slides the region window — it now drags the arranger time selection's free edge by one snap-grid step per press (the zoom-adaptive visible grid, `030-ui-design.md` § Arranger Navigation), so it is a *selection* control, not a region one, and only `⌘/Ctrl+L` commits it to the region. `⌥←`/`⌥→` jumps the cursor to the next clip edge on the selected track and `⇧⌥←`/`⇧⌥→` drags the selection's free edge there — the everyday keyboard way to select exactly one clip (cursor on its start, `⇧⌥→`) before `⌘/Ctrl+L`; `⌘/Ctrl+←`/`→` (ghost-nudged, committed on ⌘/Ctrl release) moves the marqueed block. See `020-views-and-state.md`. `SHIFT+UP`/`SHIFT+DOWN` used to set the region start/end straight to the cursor (`TransportCommand::SetRegionStartToCursor`/`SetRegionEndToCursor`); those commands had no other caller, so they were deleted rather than left dead when the binding moved — `SHIFT+UP`/`SHIFT+DOWN` now drag the arranger time selection's *track* span instead, the vertical twin of `SHIFT+L/R` (`Display::nudge_time_selection_track`, see `020-views-and-state.md`), and the region has no direct-to-cursor shortcut left at all. `Delete`/`Backspace` no longer touch the region at all — see "Arranger Time Selection — the Marquee" in `020-views-and-state.md`, which it now keys off instead (scoped to whichever tracks the marquee spans, not always every track), as does `⌘/Ctrl+E` (splits clips at the cursor, Ableton-style — moved off bare `E`, same section), `⌘/Ctrl+I` (inserts silence at the selection start, Ableton/Bitwig-style, reusing `⌘/Ctrl+E`'s split machinery, always every track regardless of the marquee's track range, moved off bare `I` — same section), `⌘/Ctrl+Delete` ("Delete Time" — the exact opposite of `⌘/Ctrl+I`: carves the selection out non-rippling, reusing `Delete`/`Backspace`'s own carve machinery, then shifts everything after it back to close the gap, always every track — same section) and `Shift+⌘/Ctrl+D` ("Duplicate Time" — insert silence at the selection *end* across every track, then paste the copied slice of every track into the gap, advancing the selection so repeated presses chain; a loop region within/after the selection is slid along, not resized; keyboard-only, like `⌘/Ctrl+S`/`⌘/Ctrl+Z`). Plain `⌘/Ctrl+D` is the everyday **"Duplicate Clips"**: paste a copy of the marquee's content flush after itself on the marqueed tracks only, *overwriting* (carving) whatever already sits there — nothing shifts, no time is inserted, tracks outside the marquee are untouched — and the marquee advances onto the copy so presses chain. Same ⇧-means-wider shape as `⌘/Ctrl+C` vs `Shift+⌘/Ctrl+C`. **There is no bare `D` (plain Duplicate) binding at all** — `⌘/Ctrl+D`/`Shift+⌘/Ctrl+D` cover every duplicate need. `Q` (Quantize) is marquee-only — only the notes inside the selection, on the marqueed tracks, nothing split — and a no-op without one; the selected-clip quantize was deleted rather than kept as a fallback, and there is no `Q` binding outside the Arranger at all. `⌘/Ctrl+A` (Select All — marquees the hull of every clip, keyboard-only like the other `⌘/Ctrl` chords), `⌘/Ctrl+L`, `SHIFT+L/R`, `SHIFT+U/D`, `⌘/Ctrl+D`, `Delete`/`Backspace`, `⌘/Ctrl+Delete`, `⌘/Ctrl+E`, `M`, `Q`, `⌘/Ctrl+I`, plain `←`/`→`, `+`/`=`/`-` and bare `Z`/`X` are the keys bound in `Display` rather than `input_handler.rs` — see `020-views-and-state.md` for why, and for how the marquee is captured and cleared.

## Transport

Cubase-style, layered on top of `Space`'s existing Ableton-style toggle rather than replacing it — all three are always live, in every non-modal view:

- **`Space`**: `TransportCommand::TogglePlayback` — starts if stopped, stops if running (position stays where it stopped).
- **`⌥Space`**: Cubase's "Start" — an unconditional restart regardless of whether playback is already running, so it jumps without a stop press first. In `Clip` it restarts from the **clip cursor** (`SequencerCommand::PlayFromClipCursor` → `TransportCommand::PlayFromTick`, `stop(); jump_and_chase(tick); start()`) and leaves the arranger cursor where it is, while bare `Space` still starts from the arranger cursor. Park the arranger cursor before an edit, work in the clip view, and `Space` replays the edit in context while `⌥Space` plays from where you're editing (the two cursors: `archive/210-docked-clip-panel.md`). In `Arranger` it is the same as bare `Space`. Both `⌥Space` arms are matched ahead of the bare `Space` arm in `input_handler.rs`. Moved off bare `Enter` (2026-09-25), which is now spare.
- **`0`**: `TransportCommand::Stop` — an unconditional stop that also resets the cursor-side position (`reset_playback_to_cursor`), paired with `⌥Space`'s "Start". `Period` used to send the same command as a main-row alternate but was freed for `Commit` (below) once `0` alone covered Stop. Because egui-winit maps `Numpad0`/`Digit0` to the same `Key::Num0` (there is no way to distinguish numpad from main-row for any key it merges — digits, `Enter`, `/`, `-`), the main-row `0` key is Stop too, not a numpad-only binding.
- **`Period`**: spare, freed from `Stop` (above) — do not reintroduce it there.
- **`/` (`Key::Slash`)**: `SequencerCommand::Commit` — freezes the capture into a new clip, or into the lead clip. While playing: the last pass (`CommitClipEdit::from_running_capture`). While stopped with no lead clip: the phrase detection frames it, and the clip keeps the rest of the capture outside its window (`CommitClipEdit::from_stopped_capture`, since 2026-09-25; it used to open `PendingClip`, `220-capture-without-pending-view.md`). Both go through `commit_clip_workflow` (`clip_lifecycle.rs`) and are no-ops on an empty buffer. With a lead clip under the cursor it inserts into that clip instead, as one undoable `InsertCaptureEdit` (since 2026-09-26): the last pass while playing, the detected phrase at the clip cursor while stopped (`040-phrase-detection.md`). Undoable since 2026-09-20 — ⌘/Ctrl+Z lifts the committed clip, ⇧⌘/Ctrl+Z puts it back; the buffer stays cleared either way (`050-undo-redo.md`). Moved off bare `C`, which meant hunting for it by sight after a take on the MIDI keyboard; `/` sits at a findable-by-feel edge (bottom-right corner, next to the right Shift key on the main row; top-left corner of the numpad cluster) and, like `0`, egui-winit maps `Slash`/`NumpadDivide` to the same `Key::Slash` with nothing else contending for either physical key.
- **`[` / `]`**: move the start / end edge of a clip to the cursor, undoably (`SetClipEdgeToCursor`, `ResizeClipEdit`, 2026-09-25). In `Arranger` an arrangement trim at the arranger cursor, on the clip under it or the nearest one on that side. In `Clip` a start / end marker on the lead clip at the clip cursor: `[` moves only the start (the end stays; the clip keeps its place in the arrangement and its length follows; since 2026-09-26, it used to keep the length), `]` ends it at the nearest whole bar count. `[`/`]` always act at the cursor, playing or not, and never move the playhead (the clip's events don't change, so the current pass plays out and the next loop wrap picks up the new window). The loop region moves only while the project has one clip: then the loop is that clip, following its edges (the first stopped `/` also turns looping on), so its end can be judged against the wrap before Enter. **While the project has one clip**, `]` on it is exact: shape the loop by ear, then **`Enter` fits the tempo** so the length becomes whole bars (`SequencerCommand::FitTempo` → `FitFirstClipEdit`, undoable; works while playing, the rest of that pass may be out of phase until the wrap). With more than one clip, `]` in the clip view rounds **up** to the bar the cursor is in. The clip cursor can always go one bar past the end (`CLIP_END_HEADROOM_BARS`), so `→` then `]` lengthens as easily as `←` then `]` shortens. It replaces the retired pending view's F1, at a point you place rather than wherever the playhead is (a playhead tap was tried and dropped 2026-09-26 as too unintentional). Any modifier but ⌘/Ctrl (Nordic layouts type brackets with ⌥). Details in `020-views-and-state.md` § "Clip Edge Drag-Resize"; why in `220-capture-without-pending-view.md`.
- Numpad `1`–`9` remain unbound/available for a future scheme; same caveat about egui-winit merging them with the main row.

## Loop State

Playback loop wrapping is gated by `Transport.loop_enabled` (mirrored in `SharedAtomics.loop_enabled`, defaults `true`). `Transport::tick()` only wraps at the region boundary when `is_loop_enabled()` is true; otherwise playback runs straight through the region end. On a wrap it returns `TickOutcome::Wrapped(region_start)` (otherwise `Advanced`); the `"sequencer"` thread's tick pump re-anchors playback for that position **synchronously** — `EventHandlers::reanchor_playback` (re-seek tracks, realign the clock, release sounding notes) — before the next `Sequencer::tick`. The wrap does **not** send a `TransportEvent`: deferring the re-anchor through `transport_event_rx` let a burst of ticks drained in one wakeup run past the region end into the next clip, leaking its opening note into a CLAP instrument (a stuck note every few loops). `⌘/Ctrl+L` mimics Ableton Live's loop-region toggle via `TransportCommand::SetRegionOrToggleLoop` / `Transport::set_region_or_toggle_loop`: if the region already matches the requested bounds — the time selection — it toggles `loop_enabled` instead of re-applying the same region; setting a genuinely different region always re-enables looping. With no time selection at all the press is `TransportCommand::ToggleLoop` — a bare `loop_enabled` flip that leaves the region untouched, so `⌘/Ctrl+L`, `⌘/Ctrl+L` turns looping off and back on in place without having to re-select the band's range first. The set-or-toggle command is deliberately operand-agnostic, so any future region source routes through it rather than growing a parallel path. The region band in the timeline (`draw_region`) is dimmed when looping is disabled.
