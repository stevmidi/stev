# Trademarks

The code is free to use under `MIT OR Apache-2.0`. The name is a different
matter. This page explains how the name "Stev" may be used. The goal is that
people know which app they have and where to report its bugs. It is not meant
to stop anyone forking.

"Stev" here means the name, the logo (a robin cut into four lines, the
third in pink: `site/images/logo.svg`), and the app icon once there is one.

## Fine without asking

- **Forking, changing and redistributing the code.** That's what the licence is
  for.
- **Saying where a fork comes from**: "based on Stev", "a fork of Stev",
  "derived from Stev".
- **Packaging Stev unchanged** under the name Stev, for example in Homebrew or a
  Linux distribution. Patches that only make it build or fit the platform
  count as unchanged.
- **Writing and talking about Stev**: articles, reviews, tutorials, videos,
  talks, courses.
- **Saying your software works with Stev**, for example that it reads `.stev`
  project files.

## Please don't

- **Ship a modified version as "Stev".** A fork with its own changes needs its
  own name and its own icon. "Klang, based on Stev" is fine. "Stev", "Stev Pro"
  or "Stev Plus" is not.
- **Suggest the project endorses something it doesn't**, such as a fork, a
  service or a paid product.

## Renaming a fork

Change the name wherever users or other programs see it: the window title, the
app bundle and its bundle identifier, the name the app gives plugins and MIDI
ports, the name its MCP server gives AI clients, and the folders it keeps
settings and logs in. That last one also keeps a fork from sharing settings,
or the AI agents' socket, with an installed Stev. The `.stev` project format
and its extension can stay, since files that open in both apps help everyone.

## Questions

Not sure whether something is fine? Open an issue on
[stevmidi/stev](https://github.com/stevmidi/stev) and ask.
